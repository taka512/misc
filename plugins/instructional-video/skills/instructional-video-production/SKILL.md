# 説明動画制作スキル

ユーザーから受け取った **台本・静止画・録画** を素材に、台本から生成したナレーション、字幕、説明画面、操作映像が一致した動画を作る。次の修正に再利用できるよう、編集データを残して納品する。

## 進め方の全体像

1. 素材と制作条件を整理する
2. 場面構成を提案し、**ユーザーの合意を得る**
3. 全文ナレーションを生成し、**ユーザーの確認を得る**
4. 説明画面と字幕を設計し、主要場面をプレビューする
5. 共通タイムラインで映像・音声・字幕を合成する
6. 書き出した完成動画そのものを検証する
7. 修正依頼を反映し、影響範囲を再検証する

2 と 3 はユーザーの確認を待つ関門。待っている間に素材調査やプレビューの準備は進めてよいが、**返答がないことを承認とみなさない**。ユーザーが構成や音声の判断を明示的に任せている場合は、その指示に従う。

## ツール

作業を始める前に、このスキルのディレクトリにある [scripts/setup_env.sh](scripts/setup_env.sh) で環境を確認し、不足があれば導入する。

```bash
bash <スキルのディレクトリ>/scripts/setup_env.sh --check   # 確認のみ（不足があれば終了コード 1）
bash <スキルのディレクトリ>/scripts/setup_env.sh           # 不足分を導入
```

- FFmpeg は Homebrew（macOS）または apt（Linux、sudo が必要）で導入する。どちらも使えない環境では手動導入を案内して止まる。
- Python ライブラリは専用の仮想環境（既定 `~/.cache/instructional-video/venv`、`VIDEO_VENV` で変更可）に入れる。以降の Python 実行は `<venv>/bin/python`、音声生成は `<venv>/bin/edge-tts` を使う。
- 導入後も、各ツールの最新の使い方や利用可能な音声・フォントは実行時に確認する。

| ツール | 用途 |
|---|---|
| FFmpeg / ffprobe | 素材解析、フレーム抽出、切り出し・速度調整・合成、音声処理、書き出し、検証 |
| Python + Pillow | 説明画面、図解、字幕の透過 PNG、場面一覧（コンタクトシート）の生成 |
| Python + NumPy | 音声サンプルの配置、完成音声の同期検証 |
| edge-tts | 台本からのナレーション生成と、発話時刻（WordBoundary）の取得 |

> **外部送信の注意**: edge-tts は Microsoft のオンライン音声合成を使うため、読み上げテキストが外部へ送信される。台本に個人情報・顧客情報・社外秘が含まれる場合は、送信してよいかを事前に確認し、必要ならダミーに置き換えるかローカル音声合成を使う。既に承認がある場合は重ねて確認しない。

## 1. 素材と制作条件を整理する

- 用途、画面比率、尺、台本をどこまで変えてよいかを依頼から読み取る。通常の制作判断は自分で進める。
- ffprobe で各素材の解像度、縦横比、尺、fps、音声の有無を調べる。
- 録画は冒頭・途中・末尾と主要操作の前後からフレームを抽出し、実際に何が映っているかを目で確認する。
- 原素材には手を加えず、`work/`（編集データ）と `output/`（完成品）を分けて保存する。

## 2. 場面構成を決める

台本には「どの発話で、どの画面に切り替えるか」が含まれることが望ましいが、秒数の指定までは求めない。

- 切り替え指示があればそれに従う。足りない部分は素材を見たうえで自分で補い、**ユーザーに台本を書き直させない**。
- 構成案は次の列を持つ表にし、ユーザー指定の部分と補った部分を区別して示す。

  | # | ナレーションの範囲 | 画面に出す要点 | 使用素材・録画区間 | 切り替えの基準 |
  |---|---|---|---|---|

- 文の区切りを機械的に画面の切り替えにしない。複数文で同じ画面を保つことも、文の途中で切り替えることもある。
- 手順や仕様は台本・素材で裏付けが取れる範囲で書き、分かりやすさのために未確認の挙動を補わない。
- 「入力」「実行」「確認」「結果表示」を分けて扱い、説明している操作と録画内の操作を一致させる。
- 秒単位のタイミングは、合意後に生成音声の発話時刻と操作に必要な時間から決める。構成を変えない微調整は自分で行う。

## 3. ナレーションを生成して確定する

短いサンプルで済ませず、本番品質の全文音声を作ってから確認してもらう。

- **表示用テキスト**（字幕）と **読み上げ用テキスト** を分け、対応関係を保持する。略語や固有名詞の読みを直しても、字幕を読み仮名にしない。
- 声・言語・速度を選び、文または段落単位で生成する。細切れにしすぎて抑揚や間が不自然にならないようにする。
- 生成時に **WordBoundary などの発話時刻を必ず保存** する。字幕を文字数比で割り振らない。
- 音声ファイルと発話時刻は同じ生成回のものを一組として扱い、混ぜない。
- 全文を通して聞ける音声を提示し、読み・抑揚・間・速度の確認を依頼する。指摘箇所は該当部分だけ再生成し、時刻も更新して全文を再提示する。
- 確定した音声は再生成せずに本番で使う。

## 4. 説明画面と字幕を設計する

デザイン指定がなければ [design-guide.md](references/design-guide.md) の基準に従う。背景・共通部品は [scripts/make_template.py](scripts/make_template.py) で生成できる。

- テンプレートは見た目をそろえるためのもので、本文の型ではない。各場面で何を理解してもらうかを先に決め、それに合う図解・段組み・強調を設計する。
- ナレーション全文を画面に載せない。画面には要点や関係図、字幕には発話内容を出す。
- 提供された静止画・録画を実際に使う。重要な操作や結果を、作り直した架空の画面で置き換えない。
- 素材は縦横比を保って配置し、字幕領域を先に確保したうえで、ボタンや結果表示が隠れない大きさにする。
- **字幕は画面下中央、白文字、最大 2 行**。意味の切れ目で改行し、長い文は発話単位に分けて単位ごとに表示時刻を持たせる。
- 全編を書き出す前に、種類の異なる主要場面の静止プレビューを作り、文字量・はみ出し・可読性を確認する。

## 5. 共通タイムラインで合成する

場面ごとに「使用素材と切り出し区間」「映像の開始・終了」「音声の配置時刻」「字幕の表示区間」を `timeline.json` に記録し、合成・字幕出力・検証のすべてでこれを使う。

- 字幕の表示時刻 = 音声の配置時刻 + 発話時刻。場面の開始時刻や音声ファイルの長さで代用しない。
- 操作映像は重要な操作ごとに区切って説明のタイミングに合わせる。動画全体を一律に伸縮して尺を合わせない。速度調整や結果画面の静止は、操作が判別できる範囲で使う。
- 音声は音量をそろえて PCM にし、共通タイムライン上に配置する。無音は **実際の無音サンプル** で埋める。
- **AAC などに圧縮した短い音声を隙間付きで連結しない**（隙間が消えて後半ほどずれる）。連続した PCM を組み立ててから、納品形式へ一度だけエンコードする。
- 場面ごとに映像を作る場合は、フレーム数と音声サンプル数の端数を管理し、誤差を累積させない。

## 6. 完成動画を検証する

中間データではなく、書き出した最終ファイルを検証対象にする。

- **音声同期**: 完成動画から音声を抽出し、元音声と波形照合して各発話の位置を確認する。冒頭だけでなく中盤・終盤・場面の境目も確認する。
- **字幕表示**: 発話の前・最中・後のフレームを抽出し、字幕が正しい時刻に切り替わっているかを見る。
- **説明と操作の一致**: 操作場面は連続フレームで確認し、ナレーションと実際の操作が一致しているかを照合する。
- **見た目**: 用語の統一、操作の順序、文字のはみ出し、重要箇所への重なり、空白フレームを確認する。
- **書き出し**: 全編がエラーなくデコードできることを確認する。

実際に音を聞いて確認できない場合は、数値による確認と聴感による確認を分けて報告し、「聞いて問題なかった」と書かない。

## 7. 修正を反映する

- 指示から変更対象を特定する。ユーザーが不要とした修正案を後の編集に混ぜない。
- 文言の変更は、ナレーション・字幕・見出し・手順・補足のすべてに反映する。用語の全体変更を求められたら、指摘された一か所だけで終わらせない。
- 音声を変えたら発話時刻も更新し、尺が変わった場合は後続の映像・音声・字幕を `timeline.json` から再計算する。
- 録画内の UI 文字を差し替える場合は、編集用コピー上で該当領域と表示区間に限定して行い、原素材は変更しない。
- 修正版を書き出し、影響範囲を再検証する。尺が変わった場合は終盤まで同期を確認する。

## 納品

- 完成動画の保存先、尺、反映した変更を簡潔に伝える。
- 字幕ファイル（SRT）や音声単体は、依頼や用途に応じて添える。
- 台本（表示用・読み上げ用）、発話時刻、`timeline.json`、生成スクリプトを `work/` に残し、次の修正で再利用できるようにする。
